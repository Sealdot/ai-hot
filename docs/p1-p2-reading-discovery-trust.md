# P1 + P2：阅读发现与内容判断

## 目标

在不引入登录、云端账户或外部服务的前提下，让 AI HOT 的单机读者完成三件事：快速决定今天要读什么、可靠地找回过去内容、在打开原文前理解内容的时效和来源上下文。

## 设计原则

- 阅读状态、笔记和偏好只存储在本机 SQLite。
- 信源同步健康度只描述抓取状态，不对报道真实性下结论。
- 多源提示仅在已有编辑事件聚合识别出两个及以上来源时展示。
- 偏好只能轻量调整同一优先级区间中的排序，不能替代编辑精选。

## P1：阅读工作台与组合检索

### 功能

1. 新增 `#/reading` 阅读工作台，包含：
   - 近 72 小时的精选未读（“今天该读”）；
   - 收藏内容；
   - 包含个人笔记的内容；
   - 未读、收藏、笔记的本机统计摘要。
2. 列表搜索覆盖标题、摘要、标签、来源名和个人笔记。
3. 列表可组合使用时间、主题、阅读状态、信源类型、具体信源和关键词筛选；状态完整保存在 hash URL。

### 用例与验收

| 用例 | 用户动作 | 预期结果 |
| --- | --- | --- |
| 晨间决策 | 打开“阅读” | 首屏给出近 72 小时未读精选和数量，无需先筛选 |
| 稍后阅读 | 收藏一篇文章后进入“阅读” | 收藏区出现该文章，按最近收藏排序 |
| 回找笔记 | 搜索笔记中写过的词 | 命中包含该词的文章，且保留其他筛选条件 |
| 精确检索 | 选择模型、某一信源、收藏 | 只展示同时满足三项的内容；刷新或返回后状态仍在 |

## P2：判断信号与偏好反馈

### 功能

1. 每个公开内容 API 返回：
   - 发布时间对应的时效档位；
   - 信源的最近抓取状态与最近成功时间；
   - 编辑审核状态；
   - 已识别事件中的独立报道来源数量和名称。
2. 卡片提供紧凑的时效/信源同步/多源信号，详情页给出解释和来源清单。
3. 在详情页提供“多看 / 少看此主题”和“多看 / 少看此信源”。反馈按文章与维度幂等存储，并聚合成本机偏好权重。
4. 精选流和阅读工作台在原有编辑优先级之后轻量应用偏好分；API 返回已应用的偏好数，界面明确说明排序依据。

### 用例与验收

| 用例 | 用户动作 | 预期结果 |
| --- | --- | --- |
| 快速判断 | 扫读卡片 | 能看到内容时效和信源同步是否正常；“多源”仅在两家以上来源时出现 |
| 深入核查 | 打开多源文章 | 能查看相关来源名称、审核状态和信源同步说明 |
| 减少噪声 | 选择“少看此主题” | 本地记录更新，下一次精选排序中该主题得到轻量降权而内容未被删除 |
| 改变主意 | 对同一维度改选“多看”或清除 | 同一条反馈被替换或删除，不会因重复点击无限叠加 |

## 本地接口与数据

- `reader_feedback`：按 `(item_id, dimension)` 保存主题或信源的 `-1 / +1` 反馈。
- `GET /api/public/reader/workspace`：返回阅读工作台分区、统计和已启用偏好数量。
- `POST /api/reader/feedback`：写入或清除本机偏好反馈；与阅读状态写接口一样限制同源请求。
- `GET /api/public/items` 和详情接口增加 `source`、判断信号、反馈状态及本机排序元数据。

## 验证策略

- SQLite 测试：反馈幂等、改选/清除、工作台统计与隐藏内容排除。
- API 冒烟：组合筛选、笔记搜索、反馈写入和判断信号。
- UI 验收：桌面与 390px 移动端均能进入阅读工作台、筛选、查看判断信号并提交反馈。
